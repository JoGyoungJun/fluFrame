## What went well

- **Two post-cutoff behaviours were measured instead of assumed.** A
  probe established that Riverpod 3's `ref.invalidate` reuses the notifier
  instance, leaves `ref.mounted` true, and lets a pre-invalidation
  operation write state afterwards without error — which is exactly the
  bug the pagination work had to prevent. The guard's regression test was
  then verified to *fail* with the guard removed. Neither fact came from
  memory, and one of them contradicted the intuitive answer.
- **An existing gate caught new work.** The "no fluFrame branding reaches
  a generated app" test failed on the `add feature` anchors — correctly,
  since anchors ship verbatim. The fix narrowed the exemption to exactly
  one regex-matched shape rather than loosening the guard, and the
  template's prose was reworded instead of exempted.
- **Every issue landed the same day it was branched**, one PR at a time,
  with the MERGED-poll rule from the 0.7.0 incident honoured throughout.
  No PR needed `gh pr update-branch`.
- Scope discipline held: two defects found *while verifying other work*
  (#103, #105) were filed with full acceptance criteria and **not**
  worked, because the cycle only works issues the user approved.

## What went poorly

- **"Announce" is now unfinished in three consecutive retros**
  (v0.7–v0.8, v0.9–v0.10, v0.11–v0.14). The traffic data is unambiguous:
  two unique visitors in fourteen days and zero external referrers, while
  the product went 0.8.0 → 1.3.0. This is past a process smell.

  The system cause is not forgetfulness. It is that the only lever that
  moves adoption sits outside the automated loop, so each cycle
  reliably produces engineering and reliably produces no distribution —
  and restating the same action item a fourth time would be the actual
  mistake. The item below is deliberately reduced to something that takes
  two minutes instead of a launch.

- **The `/release` skill had drifted from the code.** It says `cliVersion`
  lives in `command_runner.dart`; it moved to `lib/src/version.dart` in
  0.14.0. The release still worked because the drift was noticed, but a
  document that is only read during a release rots between releases.

- **`check_example_drift.dart --fix` cannot add ARB strings.** Both #101
  and #100 required hand-editing the same keys into six example ARB files
  after `--fix` reported success on everything else. The tool correctly
  refuses to overwrite ARBs the examples extend, but "correctly refuses"
  and "leaves the user to do it by hand twice in one milestone" are
  different bars.

- **The default-platform e2e still cannot run locally** (Windows
  Developer Mode off, issue #13), so Windows regressions in the shipped
  platform set are caught only by CI. Unchanged for several milestones.

## Summary

The milestone did what it set out to do: a generated app is now clickable
at a URL, the README says what the project is for and where it loses, the
CLI is something you run more than once, and the sample feature teaches
pagination correctly rather than naively — four issues, four merges, no
carry-over, and both test suites materially larger. It also produced the
clearest evidence yet that this is not the constraint. Downloads, likes,
stars and unique visitors are all where they were five days and five
releases ago, and every referrer is still a machine. The product has been
ready to talk about since 1.0.0; the next honest milestone is one that
either includes talking about it or stops pretending that is coming.
