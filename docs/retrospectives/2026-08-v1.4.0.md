## What went well

- **Planning found more than it was given.** The milestone was seeded with
  four existing P2 issues. An audit against the actual source before
  committing to scope turned up three *shipped* bugs nobody had filed —
  `add feature` writing `MapEntry(billingTitle: Billing).key` into every
  user's `app_en.arb` since 1.3.0, `doctor` promising "All set" to a machine
  about to fail `flutter pub get`, and both auth guides instructing the exact
  initialization order the addons were written to avoid. All three were in
  released code. None would have been found by working the issues as filed.

- **Two fixes found further bugs while landing.** Turning on ARB value
  comparison in #109 immediately surfaced that both example apps' `app_ja.arb`
  still carried `FluFrame アプリ` — every Japanese-locale run of both examples
  had been showing fluFrame's name. And #110's audit found `/cycle`'s own
  Phase 3 describing a manual `dart pub publish` that would have bypassed
  every release gate on an irreversible operation. That one was fixed
  *during* the cycle that then performed the release correctly.

- **A guard was narrowed, not loosened, for the second milestone running.**
  #119 needed the generated app's `AGENTS.md` to name `fluframe add feature`,
  which the "no fluFrame branding reaches a generated app" test forbids. The
  exemption was cut to three exact shapes — a `fluframe <subcommand>`
  invocation, the scaffolder's anchor tokens, and `.fluframe.json` — and
  `Welcome to fluFrame!`, `class FluFrameApp {}` and
  `See the fluFrame repository.` were each verified to still fail.

- **The plan stated an adoption hypothesis instead of implying one**, which
  was the v1.3.0 retro's action item 2. It also established something no
  previous plan had: **dependent repos and dependent packages are
  structurally 0** for this project, because a generated app carries no
  `fluframe` manifest entry. Two of the three goals every prior milestone was
  measured against were arithmetic, not distance.

## What went poorly

- **No local toolchain.** Neither Flutter nor Dart was installed on the
  machine running the cycle, so `/verify` could not run at all and CI became
  the only gate. It held — all twelve PRs went green across the full matrix,
  and the publish workflow re-ran every gate — but a one-character fix in
  #112 cost three CI round-trips (a `dart format` shape, then an `@@locale`
  key my own test's `@`-prefix filter matched by mistake) that would each
  have been a two-second local failure. Roughly half the cycle's wall clock
  was spent waiting on CI for errors a local run would have caught instantly.

- **#103's stated verification gate was vacuous, and the issue said so
  confidently.** Its acceptance criteria named `check_example_drift` as what
  would catch a forgotten examples fix. `lib/l10n/` is on
  `intentionallyDivergent` and the checker compared key *sets*, never values,
  so it passed identically before and after. The readiness audit caught it;
  had the issue been worked as written, the box would have been ticked
  against a check that proves nothing.

- **"Announce" is now unfinished in four consecutive retros.** The v1.3.0
  retro reduced it to "one link, twice" and said explicitly that if it did
  not happen again, the next plan should say so rather than plan around it.
  It has not happened. What is different this time: the draft is written,
  version-current, demo-first, and paste-ready, both pre-post blockers are
  cleared, and v1.4.0 is live — so the remaining work is genuinely a human
  opening two browser tabs. There is nothing left to prepare.

- **The `/cycle` failure rule was exceeded, deliberately.** It allows one fix
  attempt on a red CI before abandoning the branch. #112 took two and #116
  took two. Both were exact, diagnosed failures rather than thrashing, and
  the rule is calibrated for a world where `/verify` runs locally and a red
  CI means something surprising. It should say so.

## Summary

Eleven issues, eleven merges, one release, no carry-over. The milestone did
what it set out to do and found three shipped bugs doing it — a generator
writing malformed strings into users' source, a doctor that diagnosed
nothing, and guides that reproduced a boot failure the code already knew
about. It also removed a supply-chain path from a mutable action tag to a
pub.dev publish, and corrected the project's own statement of its goal after
establishing that two of the three criteria it had been chasing cannot move.

The numbers are unchanged, and now demonstrably not the point: 608 downloads
that pub.dev's own docs say are mostly CI, three unique visitors in fourteen
days, and no referrer that is a person. The product has been ready to talk
about since 1.0.0. It is now also correct in the places a first visitor would
have looked. The only thing left is the two browser tabs.
