## What went well

- **The design-first routine earned its keep on the first try**: the
  spec's decisions (gate only `/profile`, redirect owns all navigation,
  fake repo with a real failure rule) held through implementation with
  a single documented deviation, and the AC list translated directly
  into the integration tests.
- **Zero-dependency auth proved out**: login → gated tab → persisted
  session → sign-out, all testable offline (43/43), with real backends
  reduced to a one-provider swap documented in two guides.
- Riverpod 3's undocumented corners (router `refreshListenable`) were
  resolved by reading the pinned package source before coding — the
  ChangeNotifier bridge worked first time.

## What went poorly

- The uncertain `provider.listenable` export forced a mid-design
  fallback plan; harmless here, but post-cutoff API checks should land
  in the spec phase, not during implementation. (Adopted: spec §3 now
  cites the verified source line — keep doing that.)
